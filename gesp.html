考场提交前 7 步

从 Word 原文里抽出的主线：读题、手算、定变量、写代码、跑样例、测边界、再提交。每一步都很小，但能挡住很多低级错误。

1

认真读题两遍

尤其看括号、样例解释、输入输出格式和数据范围。先把样例为什么得到输出想清楚。

2

用草稿纸手算

遇到循环、数组、字符串、选择题时，先模拟一轮状态变化，别急着敲代码。

3

先定变量类型

三级以上编程题，整数优先考虑 long long；多组样例里的 sum、flag、cnt 每次重置。

4

写完整框架

头文件、main、return 0、分号、输入输出格式先搭好，避免 CE 类小错。

5

跑完全部样例

严格对照大小写、空格、换行、逗号，Yes/No 这种输出不要凭感觉。

6

自造边界数据

多试 0、1、最大值、最小值、只有一个元素、全部相同、升序/降序等情况。

7

错了先读报错

TLE 查复杂度和死循环，WA 查逻辑和边界，CE 查语法，RE 查越界、除零和递归。

✓

时间不够先跳题

卡住时不要硬扛。先把能拿的分拿到，再回来逐字检查这道题。

Daniel 重点坑点

这些都是小学生编程考级里特别容易丢分的地方：写错一个字符、漏一次初始化、输出多一个空格，都可能从会做变成 WA。

循环变量

i / j / k 别串台

双重循环里外层是 i、内层是 j，复制代码后一定检查自增变量和数组下标。

for (j = 1; j <= n; j++)  // 不是 i++
判断条件

= 和 == 分清楚

判断时可以把常量写在前面，减少把赋值当判断的机会。

if (1 == flag) { ... }
初始化

多组数据每轮清空

sum、cnt、flag、数组、最大最小值，都要确认初始化位置是不是在每组数据开始处。

整数范围

int 不够就用 long long

看到乘法、累加、排序后的总和、很大的 n，先判断是否会超过 int。

字符串数组

索引和长度不是一回事

下标通常是 0 到 n-1，长度通常是 1 到 n。循环变量到底代表下标还是长度，先写清楚。

输出格式

大小写、空格、换行

Yes/No、每行输出几个数、末尾是否换行，都要照题目，不要用自己的习惯。

错误反馈速查

提交后没过时，先按反馈类型缩小范围。不要一上来全改，先找到最可能的那一类问题。

TLE

超时。查死循环、复杂度、重复计算、输入输出效率。

MLE

内存超限。查数组太大、缓存太多、递归太深。

CE

编译错误。查分号、括号、头文件、变量名、函数参数。

WA

答案错误。查逻辑、边界、数据范围、输出格式。

RE

运行错误。查数组越界、除以零、栈溢出、非法访问。

我补充的小学生 GESP 易错清单

在原文基础上，再补一些 GESP 和入门竞赛常见坑，适合考前最后一天快速过一遍。

读入

cin 混 getline

如果先用 cin 再 getline，中间可能残留换行。需要先处理掉换行，或者统一读入方式。

数组

开大一点，但别离谱

数组大小要覆盖最大 n。下标从 0 还是 1 开始，全题保持一致。

除法

整数除法会截断

平均数、比例、小数输出时，确认是不是需要 double，别让 5 / 2 变成 2。

排序

排序区间左闭右开

vector 常用 sort(a.begin(), a.end())；数组从 1 开始时常用 sort(a+1, a+n+1)。

二分

边界必须能收缩

while 条件、mid、l/r 更新要保证每轮范围变小，防止死循环。

审题

“不正确的是”要圈出来

选择题里“不对”“不能”“至少”“至多”都要标记，别把题目方向读反。

    # 编程竞赛常见错误反馈及解决方式汇总

  82. 82

    在编程竞赛和日常编程中，常见的错误反馈包括TLE、MLE、CE等。以下是这些错误的详细解释和解决方法：

  83. 83

    ## 1. TLE (Time Limit Exceeded) - 时间超出限制

  84. 84

    **原因**：程序运行时间超过了题目规定的限制。

  85. 85

    **解决方法**：

  86. 86

    - **优化算法复杂度**：检查是否使用了最优算法（如将O(n²)优化为O(nlogn)）

  87. 87

    - **减少循环次数**：避免不必要的嵌套循环

  88. 88

    - **使用更高效的数据结构**：如用哈希表替代线性搜索

  89. 89

    - **避免重复计算**：使用记忆化或动态规划

  90. 90

    - **检查输入输出效率**：

  91. 91

    - C++中使用`ios::sync_with_stdio(false); cin.tie(NULL);`

  92. 92

    - Java中使用BufferedReader替代Scanner

  93. 93

    - Python中使用sys.stdin.readline

  94. 94

    - **提前终止**：在满足条件时及时break或return

  95. 95

    - **注意语言特性**：Python在某些情况下较慢，可能需要换用PyPy或C++

  96. 96

    ## 2. MLE (Memory Limit Exceeded) - 内存超出限制

  97. 97

    **原因**：程序使用的内存超过了题目规定的限制。

  98. 98

    **解决方法**：

  99. 99

    - **检查数据结构大小**：估算所需内存是否合理

  100. 100

    - **释放不必要的变量**：及时删除不再需要的大对象

  101. 101

    - **使用更紧凑的数据结构**：

  102. 102

    - 用位运算代替布尔数组

  103. 103

    - 使用更小的数据类型（如short代替int）

  104. 104

    - **避免过度缓存**：不要预先存储所有结果，考虑即时计算

  105. 105

    - **优化递归**：过深的递归可能导致栈溢出，改为迭代实现

  106. 106

    - **检查无限循环**：可能导致内存不断增长

  107. 107

    ## 3. CE (Compilation Error) - 编译错误

  108. 108

    **原因**：源代码无法通过编译。

  109. 109

    **解决方法**：

  110. 110

    - **检查语法错误**：括号不匹配、缺少分号等基本语法问题

  111. 111

    - **检查语言标准**：确保使用的特性在评判系统支持的语言版本中可用

  112. 112

    - **检查拼写错误**：变量名、函数名拼写是否正确

  113. 113

    - **检查头文件/导入**：确保所有需要的库都已正确包含

  114. 114

    - **检查未声明的标识符**：所有变量和函数是否已正确定义

  115. 115

    - **检查类型匹配**：函数参数和返回值类型是否正确

  116. 116

    - **注意语言差异**：如Java类名必须与文件名一致，Python缩进要求等

  117. 117
