先认清四种文件操作方式

人们常把文件流归入“STL 学习”，更准确地说，它属于 C++ 标准库的流体系。前三种包含 <fstream>；freopen 来自 <cstdio>。

1

ifstream

input file stream，从文件读入。用法像 cin，只是数据源变成文件。

ifstream fin("input.txt");
int x;
fin >> x;
2

ofstream

output file stream，向文件写出。必须对 fout 使用 <<。

ofstream fout("out.txt");
fout << 42;
3

fstream

同一个流既能读也能写。四级先会辨认，并知道打开模式可以组合。

fstream file("data.txt",
  ios::in | ios::out);
4

freopen

把标准输入输出整体改道；之后仍写 cin/cout。

freopen("in.txt","r",stdin);
freopen("out.txt","w",stdout);

读写流程与打开模式

考试读代码时沿着“创建流 → 检查打开 → 读写 → 关闭”检查，再判断数据到底流向哪里。

① 创建并关联文件

ifstream fin("score.txt"); 可一步完成，也可先声明再 open()。

② 检查是否打开

if (!fin.is_open()) 能判断路径或权限问题。

③ 在读取成功时处理

写 while (fin >> x) 或 while (getline(fin,line))，不要先问 EOF。

④ 结束并关闭

close() 会结束关联；写文件时也会刷新缓冲区。

模式含义四级判断要点
ios::in读取ifstream 默认输入。
ios::out写入ofstream 默认输出，通常覆盖旧内容。
ios::app末尾追加日志常用，不清空旧数据。
ios::trunc打开时清空普通输出流常见默认行为。
ios::ate打开后定位末尾仍可重新定位，不等同强制追加。
ios::binary二进制模式拓展认知；四级多考文本文件。

完整文件流知识图谱

小葵先把绿色“四级必会”练熟，再了解红色“拓展认知”。高级接口不要求一次背完，重点是知道它们负责什么。

读入方法 四级必会

fin >> x格式化读取；跳过空白，按变量类型读取。
getline(fin,s)读取完整一行，保留行内空格，不保存换行符。
fin.get(ch)逐字符读取，空格和换行也能读到。
fin.ignore(n,'\n')忽略字符，常用于清除 >> 后残留的行尾。
fin.peek()查看下一个字符但不取走，属于拓展用法。

写出方法 四级必会

fout << x格式化写出；用法和 cout 相同。
fout.put(ch)写出一个字符，包括空格或换行。
fout.flush()立即刷新缓冲区；endl 也会换行并刷新。
fout.write(p,n)定长写出 n 字节，常用于二进制文件。
'\n' / endl'\n' 只换行；endl 还会刷新，频繁使用可能较慢。

流状态 四级必会

is_open()文件是否成功打开；只管“是否关联文件”。
eof()上一次读取因为到达文件末尾而失败。
fail()格式不匹配、文件未开等可恢复失败。
bad()更严重的底层读写错误。
clear()清除错误标志；若要继续读取，还需处理导致失败的数据。

位置与缓冲区 拓展认知

tellg / seekg查询或移动输入位置；g 可理解为 get。
tellp / seekp查询或移动输出位置；p 可理解为 put。
rdbuf()取得流缓冲区，可让 cout 临时写入 ofstream。
open / close先声明后打开；同一流重新 open 前应先 close。
相对路径相对于程序的当前工作目录，不一定是源代码所在目录。

按格式读取数字

和 cin 一样自动跳过空白。循环条件就是“本次读取是否成功”。

稳妥写法：while (fin >> x)，不会在读取失败后重复处理旧值。
#include <fstream>
#include <iostream>
using namespace std;

int main() {
    ifstream fin("input.txt");
    if (!fin.is_open()) return 1;
    int x, sum = 0;
    while (fin >> x) sum += x;
    fin.close();
    cout << sum;
}

逐行读取文本

getline 会读取到换行符，保留一行中的空格。

混用提醒：先用 >> 后用 getline，可能要先忽略残留换行符。
#include <fstream>
#include <string>
using namespace std;

int main() {
    ifstream fin("article.txt");
    string line;
    while (getline(fin, line)) {
        // 处理完整一行
    }
    fin.close();
}

覆盖写出与末尾追加

普通 ofstream 通常清空旧内容；保留旧内容应加 ios::app。

高频坑：创建 fout 后仍写 cout，内容只到屏幕。
#include <fstream>
using namespace std;

int main() {
    ofstream fout("result.txt");
    fout << "score=" << 100 << '\n';
    fout.close();

    ofstream log("result.txt", ios::app);
    log << "passed\n";
    log.close();
}

fstream 双向读写

同一个对象配置 ios::in | ios::out。在输入与输出之间切换时，要明确定位并检查状态。

四级重点：会辨认双向模式；seekg/seekp 属于拓展，先理解 g 是读取位置、p 是写入位置。
#include <fstream>
#include <string>
using namespace std;

int main() {
    fstream file("data.txt",
                 ios::in | ios::out);
    if (!file) return 1;

    string word;
    file >> word;       // 从文件读取
    file.clear();
    file.seekp(0, ios::end);
    file << "\nDONE"; // 在末尾写入
    file.close();
}

freopen 与 rdbuf 重定向

freopen 重新连接 stdin/stdout；rdbuf 则临时替换 C++ 流缓冲区。下面两种写法是独立方案。

模式字符："r" 读，"w" 覆盖写，"a" 追加写。使用 rdbuf 后记得恢复旧缓冲区。
#include <cstdio>
#include <iostream>
#include <fstream>
using namespace std;

void byFreopen() {
    freopen("input.txt", "r", stdin);
    freopen("output.txt", "w", stdout);
    int a, b;
    cin >> a >> b;
    cout << a + b << '\n';
}

void byRdbuf() {
    ofstream log("log.txt");
    streambuf *old = cout.rdbuf();
    cout.rdbuf(log.rdbuf());
    cout << "saved";
    cout.rdbuf(old);
}

考场最容易错的六个细节

逐行确认正在使用的是哪个流对象，以及这次读取是否真的成功。

1

建了 fout，却仍对 cout 输出

ofstream 不会自动接管 cout。

ofstream fout("a.txt");
cout << "Hi"; // 屏幕
ofstream fout("a.txt");
fout << "Hi"; // 文件
2

用 while (!fin.eof()) 读取

eof 通常在读取失败后才置位。

while (!fin.eof()) {
  fin >> x; use(x);
}
while (fin >> x) {
  use(x);
}
3

>> 后直接 getline

缓冲区残留换行符时，getline 可能立刻得到空行。

fin >> n;
getline(fin,line);
fin >> n;
fin.ignore(10000,'\n');
getline(fin,line);
4

把 app 和 ate 当成一回事

app 强制每次写在末尾；ate 只是打开后先到末尾。

ios::ate
// 等同永远追加？错
ios::app
// 追加日志更明确
5

忘记检查打开状态

路径和工作目录不同，后续读写可能全部失败。

ifstream fin("x.txt");
fin >> x;
ifstream fin("x.txt");
if (!fin) return 1;
6

rdbuf 后忘记恢复

后续若要回到屏幕，应保存原缓冲区并恢复。

cout.rdbuf(fout.rdbuf());
cout << "A";
auto *old=cout.rdbuf();
cout.rdbuf(fout.rdbuf());
cout << "A";
cout.rdbuf(old);

五道真题化样题

参考四级历年考法原创改编：判断输出目标、分析混合读取、选择正确循环、辨析打开模式与流状态。

样题 1：输出去了哪里？

执行代码后，字符串出现在哪里？

ofstream outFile("log.txt");
cout << "GESP";
outFile.close();
答案：屏幕。创建 outFile 不等于重定向 cout；必须写 outFile << "GESP"。

样题 2：混合读取

文件第一行是 Happy New Year，执行下列代码后 s2 是什么？

fin >> s1;
getline(fin, s2);
答案：" New Year"。>> 读走 Happy，getline 接着读本行剩余内容，包括开头空格。

样题 3：正确统计

统计文件中成功读到的整数个数，哪种循环最稳妥？

int x, cnt = 0;
while (fin >> x) {
    cnt++;
}
答案：上面的写法。它同时处理文件结束与类型不匹配，不会重复旧值。

样题 4：追加还是覆盖？

原文件内容为 A，执行后文件内容是什么？

ofstream fout("x.txt", ios::app);
fout << "B";
fout.close();
答案：AB。ios::app 保留旧内容，并把新内容写到末尾。

样题 5：流失败后怎么办？

文件开头是字母，执行 fin >> x 读取 int 失败后，能否直接继续读？

int x;
fin >> x;   // 类型不匹配
fin.clear();  // 只清状态
fin.ignore(10000, '\n');
答案：先清状态并处理坏数据。clear() 不会自动移走导致失败的字符，通常还要 ignore。

小葵的四轮强化路线

每轮只抓一个目标：先会认方向，再会套模板，接着读代码，最后做混合题。比一次背完所有函数更牢。

第 1 轮：认方向

看到 ifstream 就说“文件到程序”；看到 ofstream 就说“程序到文件”；看到 freopen 就找 stdin/stdout。

第 2 轮：默写模板

每天默写一次读取数字、逐行读取、覆盖写出、追加写出四个短模板，重点写对流对象名。

第 3 轮：手算输出

给文件内容逐个画下划线，标出每次 >> 或 getline 消耗了哪些字符，尤其注意空格和换行。

第 4 轮：错题归因

错题只归入四类：方向错、模式错、分隔符错、状态错；同类连续做 3 题直到全对。
